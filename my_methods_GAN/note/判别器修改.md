我审完之后的判断很明确：

**你现在的问题，不是“判别器代码跑不起来”，而是“判别器设计太弱 + phase3 训练策略太保守 + FM 的定义把数值压得过小”。**
所以实验 C 才会出现你前面看到的现象：`gan_d_raw`、`gan_adv_weighted` 很快稳定在一个小值附近，`gan_fm_weighted` 几乎为 0，最终 phase3 更像“B 的轻微扰动”，而不是一次真正有效的 GAN 微调。 

---

# 一、先说判别器代码本身有没有硬错误

## 结论

**没有明显硬错误，可以正常训练。**

你当前的判别器有两套：

* `MultiResolutionDiscriminator`：3 个 `_ConvDisc1D`，靠逐次 `avg_pool1d` 改变时间分辨率。
* `MultiBandDiscriminator`：把波形做低/中/高“代理频带”分解，再分别送入 `_ConvDisc1D`。

这在工程上是能工作的，而且和你 `engine.py` 里的 phase3 调用是对齐的：

* D 端：`real_mrd = mrd(clean)`，`fake_mrd = mrd(restored.detach())`
* G 端：`fake_mrd_g = mrd(restored)`，再算 `adv_g` 和 `feat_g`。

所以从“能不能跑”这个角度，没问题。

---

# 二、真正的问题出在哪里

## 问题 1：当前 MRD 其实不是“真正的多分辨率频域判别器”

你现在的 `MultiResolutionDiscriminator` 只是对**时域波形**做了三次不同程度的下采样，然后分别送入相同的 1D 卷积判别器。

这意味着它更像是：

* 多时间尺度判别器

而不是通常语音 GAN 文献里那种：

* **基于不同 STFT 配置的 multi-resolution spectral discriminator**

这会带来两个后果：

### 后果 A

它对 **codec 伪影最明显的频谱结构差异** 不够敏感。
而你的任务恰恰是 codec restoration，最该盯的是频谱结构。

### 后果 B

它和 generator 的 `SI-SDR + MRSTFT` 目标重合度不够高，导致判别器给 generator 的额外信息不强。

这也是你现在 `gan_adv_weighted` 很小、`gan_fm_weighted` 更小的一个重要原因。

---

## 问题 2：`_ConvDisc1D` 太浅、太弱

你现在 `_ConvDisc1D` 只有 4 层卷积：

* `16 → 64 → 128 → 256`
* 每层 stride=2
* 最后一个 head 输出 score。

对普通小任务能用，但对你现在这种：

* 4 秒语音
* 16 kHz
* codec 伪影
* warm-start 后只做轻量 phase3

这个 D 偏弱了。

它会导致：

* 判别器很快到一个“无聊平衡”
* real/fake 的中间特征差距很小
* `feat_g` 原始值天然就很低

这和你前面观测到的：

* `fm_loss_weight` 调到 1 仍然没用
  是完全一致的。

---

## 问题 3：`loss_feature_matching()` 的定义把 FM 数值压太小了

你现在 FM 的定义是：

* 遍历所有判别器层
* 每层 `L1`
* 最后 `torch.stack(losses).mean()`。这个在你之前的 `losses.py` 就是这么写的。

这会导致：

* 判别器层数越多
* 尺度越多
* 每层差异稍微小一点

最后 `feat_g` 的 raw 值就会很接近 0。

所以你看到：

* `fm_loss_weight=0.15` 几乎没用
* `fm_loss_weight=1.0` 还是几乎没用

不是你参数不会调，而是**当前 FM 定义本身就把值压没了**。

---

## 问题 4：phase3 的 D 更新策略太保守

你现在训练里：

* `d_update_interval = 2`
* `lr_d_max = 2e-5`
* `lr_d_min = 5e-6`
* 实验 C preset 还默认 `use_mbd=False`。 

也就是：

* 判别器更新频率低
* 学习率低
* 只开一个较弱的 MRD

这对于“保守不炸”当然有好处，但副作用就是：

**D 根本没机会把 real / fake gap 拉开。**

于是：

* `gan_d_raw` 很快稳定
* `gan_adv_weighted` 很小
* `gan_fm_weighted` 更小

这正是你现在遇到的情况。

---

# 三、我给你的判别器修改建议

## 建议 1：把 MRD 改成“STFT 判别器”

这是我最推荐的核心修改。

### 当前问题

你现在的 MRD 还是在看时域波形。

### 更合理的做法

对同一段 waveform，做多组 STFT：

* `(n_fft=256, hop=64, win=256)`
* `(n_fft=512, hop=128, win=512)`
* `(n_fft=1024, hop=256, win=1024)`

把每组的：

* `log |STFT|`
* 或者 `[real, imag]`
* 或 `[mag]`

送入一个 2D CNN discriminator。

### 为什么这一步最值

因为 codec 伪影最明显体现在：

* 谐波结构
* 高频缺失
* 频谱平滑化
* 带宽边界

而 STFT 判别器对这些更敏感。

### 这一步的收益

你会同时改善：

* `gan_adv` 真正有意义
* `feat_g` 也更容易变得非零、有区分度

---

## 建议 2：如果你暂时不想重写 STFT 判别器，就先加强现有 `_ConvDisc1D`

最小修改方案：

### 把判别器加深一点

例如从：

```python
(16, 64, 128, 256)
```

改成：

```python
(32, 64, 128, 256, 512)
```

并且后两层加更大的感受野，比如 kernel size 41 / 21。
现在全是 `kernel_size=15`，太统一了。

### 作用

让 D 更容易分辨：

* 长时纹理
* 平滑过度的 codec 恢复痕迹

---

## 建议 3：MBD 先不要启用

这点我维持之前判断。

你现在的 `MultiBandDiscriminator` 其实不是严格频带分解，而是：

* `low = avg_pool`
* `mid = wav - low`
* `high = mid - high_smooth`

这是一个很轻的 proxy band split。

对你的任务来说，它更适合作为后续可选增强项，不适合现在这个阶段。
因为你最核心的问题还没解决，不在高频细节，而在：

* GAN 对 G 几乎没驱动力

所以我建议：

**先别碰 MBD。**

## 建议 6：把 FM 从 mean 改成更强的归约

你当前 phase3 最致命的问题之一，就是 `feat_g` raw 太小。
所以训练脚本层面最有价值的一个改动是：

### 当前

```python
losses.append(F.l1_loss(...))
return torch.stack(losses).mean()
```

### 建议

先试这两种之一：

#### 方案 A

```python
return torch.stack(losses).sum() / max(1, len(losses) ** 0.5)
```

#### 方案 B

干脆直接：

```python
return torch.stack(losses).sum()
```

这样 FM 的 raw 值会明显变大，不再被平均到接近 0。

### 为什么这一步值得

你现在已经验证了：

* `fm_loss_weight` 不是关键
* 原始 `feat_g` 才是关键

那就应该先改 `feat_g` 的数值定义。
