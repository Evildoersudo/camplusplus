可以。按你 `门控机制修改.md` 的思路，我建议方案分三步走，不直接一上来“大改全网”，否则很容易把当前已经有效的 codec 修复能力弄坏。

核心目标是：

```text
codec 输入：模型应该敢修复
clean 输入：模型应该尽量不动
```

所以方案不是单纯“多加 clean 数据”，而是：

```text
clean passthrough 数据 + 退化感知门控残差 + clean-only 正则
```

## 方案总览

### Step 1：先做 clean passthrough 对照实验，不改网络

当前生成器是：

```python
x_out = x_in + R(x)
```

第一步先不改这个结构，只让训练数据里加入 clean 样本：

```text
codec 样本：
  input = x_opus
  target = x_clean
  sample_type = codec

clean 样本：
  input = x_clean
  target = x_clean
  sample_type = clean
```

推荐比例：

```text
codec : clean = 8 : 2
```

目的不是最终方案，而是先验证：

```text
只加入 clean→clean 训练，是否能缓解 clean 输入退化？
```

如果这一步 clean 指标明显改善，说明问题确实主要来自训练分布缺失；如果改善有限，就说明必须引入显式门控。

需要改的点：

- `dataset.py`
  - 增加 clean passthrough 样本类型。
  - 返回字段增加：

```python
"sample_type": "codec" 或 "clean"
"is_clean": bool
"deg_target": 0.0 或 1.0
```

- `engine.py`
  - 训练时仍然统一算重建 loss。
  - speaker loss / feature loss 也统一算：

```text
restored vs target
```

也就是说 Step 1 不需要新 loss。

---

### Step 2：加入门控生成器，但先只训练 gate/context head

这是你文档里最关键的一步。

当前生成器在 [generator.py](/root/camplusplus/my_methods_GAN/sv_codec_restore_gan/models/generator.py) 里最后是：

```python
pred_ri_cws = self.out_proj(h)
pred_ri = self._cws_merge(pred_ri_cws, orig_freq)
pred_res = self._istft_ri(pred_ri, length=coded_16k.shape[-1])
return coded_16k + pred_res
```

要改成：

```text
pred_ri_cws = residual_head(h)
gate_band_time = gate_head(h)
deg_score = context_head(h)
gate_final = gate_band_time * deg_score
pred_ri_cws_gated = pred_ri_cws * gate_final_ri
x_out = x_in + iSTFT(pred_ri_cws_gated)
```

结构上：

```text
h
├── residual_head：原来的 out_proj
├── gate_head：Conv1x1 → GELU → Conv1x1 → Sigmoid
└── context_head：GlobalAvgPool → MLP → Sigmoid
```

门控形状：

```text
gate_band_time: [B, K, T, F_sub]
deg_score:      [B, 1]
gate_final:     [B, K, T, F_sub]
```

然后扩展到 real / imag：

```text
[B, K, T, F_sub] → [B, 2K, T, F_sub]
```

也就是同一个复谱位置的 real / imag 共用同一个 gate。

初始化很重要：

```text
gate_head 最后一层 weight = 0
gate_head 最后一层 bias = 3.0
```

这样：

```text
sigmoid(3) ≈ 0.95
```

模型刚开始近似原 baseline：

```text
x_out ≈ x_in + R(x)
```

不会一开始就把残差压没。

Step 2 训练策略：

```text
加载已有 baseline
冻结 in_proj / GridNetBlock / residual_head
只训练 gate_head / context_head
训练 1～2 epoch
```

目标是让模型先学会：

```text
clean 输入：关门
codec 输入：开门
```

而不是马上重新学习修复能力。

---

### Step 3：小学习率联合微调

Step 2 之后再解冻全部网络，用小学习率联合训练。

建议：

```text
lr = 原 phase2 学习率的 1/3 ～ 1/5
codec : clean = 8 : 2 或 7 : 3
```

这一步才让 residual branch 和 gate branch 一起适配。

## Loss 设计

重建 loss 不拆分，保持统一：

```text
L_rec =
  λ_wave L_wave
+ λ_mrstft L_mrstft
+ λ_complex L_complex
```

codec 样本：

```text
input = codec
target = clean
```

clean 样本：

```text
input = clean
target = clean
```

真正区分 sample_type 的是额外正则。

### clean-only loss

只对 clean 样本加：

```text
L_res_clean = || gated_residual ||_1 / (|| input ||_1 + eps)
L_gate_clean = mean(gate_final)
```

作用：

```text
clean 输入时，残差越小越好，gate 越关越好。
```

### degradation loss

对 clean 和 codec 都加：

```text
clean: deg_target = 0
Opus16k: deg_target = 1
```

第一版用二值监督即可：

```text
L_deg = BCE 或 MSE(deg_score, deg_target)
```

后续多码率再扩展成连续标签：

```text
clean   = 0.0
Opus32k = 0.3
Opus24k = 0.5
Opus16k = 0.7
Opus8k  = 0.9
```

### gate smooth loss

对所有样本都可以加，但权重要很小：

```text
L_smooth = TV_time(gate_final) + TV_freq(gate_final)
```

初始权重建议：

```text
0.005 ～ 0.02
```

### 总 loss

Phase 1：

```text
L =
  L_rec
+ α_clean_res  L_res_clean
+ α_clean_gate L_gate_clean
+ β_deg        L_deg
+ η_smooth     L_smooth
```

推荐初始值：

```text
α_clean_res  = 0.1
α_clean_gate = 0.1
β_deg        = 0.2
η_smooth     = 0.01
```

Phase 2：

```text
L =
  L_rec_low_weight
+ λ_spk  L_spk
+ λ_feat L_feat
+ α_clean_res  L_res_clean
+ α_clean_gate L_gate_clean
+ β_deg        L_deg
+ η_smooth     L_smooth
```

speaker loss 不需要为 clean / codec 单独写两套：

```text
L_spk = 1 - cos(embedding(restored), embedding(target))
L_feat = L1(feature(restored), feature(target))
```

## 模型选择标准

不要只看训练 loss。最终 checkpoint 选择建议用三个硬指标：

```text
1. restored EER 必须低于 coded EER
2. restored 相对 coded 的改善 ≥ 原 baseline 改善的 80%
3. clean → model 的 EER 尽量接近 clean 原始 EER
```

如果 baseline 对 coded 改善是 5%，新模型至少要保住 4% 左右；在这个前提下选择 clean 退化最小的 checkpoint。

---

我的建议是：后续实施时先做 Step 1，因为它改动最小、能快速确认 clean passthrough 的收益；然后再加 gate。这样不会一下子把变量混在一起，实验结论会清楚很多。
